# Benchmark quality criteria, version 1

## Freeze and purpose

D-12 is frozen by this document on **2026-11-07 at 19:52 UTC** before the author inspected any evaluation-model result. The policy identity is `quality-criteria-v1`. This freezes quality and claim criteria; it does not claim that any suite, model matrix, implementation, review, or gate already passes. Before a confirmatory call, retain the exact suite hash, protocol/profile, model/endpoint/settings matrix, execution budget, seeds, and this document's file hash in its experiment manifest. Later changes require an amendment with its reason and exposure history; an inspected result cannot become predeclared retrospectively.

The object measured is **three-way curvature classification of the exact scalar function on the supplied closed interval**, within the implemented verifier's accepted population. It is not general mathematical ability, causal sensitivity to nesting depth, optimization competence, or practical deployment safety. Affine/constant overlap is excluded. A sufficient composition rule being unavailable never establishes neither.

The inherited contract is three fresh trials, exact expression/domain input, deterministic extraction, pooled fixed-three macro-F1, accuracy/class metrics, and explicit infrastructure/missing-work categories. Official grades never change after a reviewer reads an explanation. Existing defaults use 4,096 output tokens and endpoint-default settings. An explicit reasoning effort or larger ceiling needs an identified profile/settings extension; its results must remain separate from unchanged version-1 comparisons.

## Admission and review criteria

1. **Reference validity:** Every admitted case passes the relevant full certificate replay on its exact domain. Convex/concave labels require a complete global proof plus strict exclusion of the opposite label; neither requires two strict counterexamples plus domain validity. No reference disagreement, unverified case, label leak, invented outcome, or invalid reference is an acceptable scoped limitation.
2. **Independent mathematics:** Each new family has a separately written derivative/inequality or exact polynomial identity, domain argument, parameter inequalities, and checked examples in all represented label regimes. Review all new family boundaries and every example used to support a failure claim. Re-running the same automatic differentiation implementation is reproducibility evidence, not an independent reference. Record automated/model-assisted reviewer roles and limits; claim human approval only when it occurred.
3. **Coverage:** The recommended new challenge target is **72 tasks: eight broad families × three labels × three parameter groups**, with one complete three-label group sharing a cluster identity. Minimum admission for a narrower challenge is **36 tasks, six broad families, and at least two tasks per family/label**. Predeclare the achieved target before running models. A smaller population may be reported descriptively; it cannot inherit the richer-coverage claim. Domain regimes, operation diversity, nonlinear branching, and candidate rejection rates must be visible. The same logarithm family in different curvature regimes is one broad family, not two diversity counts.
4. **No padding:** Exact duplicate functions on the same domain are excluded. Record bounded domain-preserving simplification, input reflection/normalization, output scaling, affine additions, and template/parameter groups. Positive output scaling and affine addition do not create a new curvature problem; negative scaling swaps convex/concave. Such variants may be controls, but one transformation cluster is one support unit for uncertainty. Do not obtain the coverage target by adding arbitrary affine offsets. Unknown semantic equivalence remains explicitly unknown.
5. **Depth honesty:** Retain raw operation depth/node occurrences, simplified diagnostic depth/nodes, unique subtree counts, operator counts, input length, active pieces where defined, and transformation/identity flags. Never relabel raw depth after simplification or alter the model input silently. Increasing depth, certificate subdivisions, or derivative size is not proof of mathematical or model difficulty. Depth plots are descriptive unless a separate matched design controls length, family, and equivalent representations.
6. **Leakage:** Outgoing inference bodies contain only the selected prompt and permitted generation fields. Exclude case IDs, ordinal/order, family names, intended/verified labels, certificates, witness coordinates, signatures, suite coverage, and previous answers. The permitted label enum in neutral instructions is not a leak. Use allowlisted request construction and sentinel metadata tests; simple substring matching is insufficient. Canonical suite ordering must never be presented as a sequence of labeled tasks. Check public/browser assets and error payloads too.
7. **Selection:** Keep candidate attempts and verifier status/reason by family, intended label, and parameter regime. This is a balanced, verifier-selected synthetic population, not a prevalence estimate for arbitrary mathematical expressions. Report failures of certification as coverage limits. Do not remove easy successes or add hard failures after confirmation starts. A revised suite is a new exploratory/confirmation cycle.
8. **Comparability:** A comparison cell fixes suite membership/order identity, prompt, answer policy, schema enforcement, trial count, output ceiling, requested reasoning/sampling settings, provider route, and requested/reported model identity. Unknown effective settings remain unknown. Model aliases and serving changes limit reproduction. Different efforts/budgets/profiles are separately named cells; a common token ceiling is not equal compute. Unsupported matrix cells remain unsupported, with no silent parameter omission or model substitution.
9. **Outcomes and denominators:** Reconcile valid-correct, valid-wrong, malformed/empty/conflicting, refusal, truncation, provider error, interruption, cancellation, and unattempted categories. Preserve retries as attempts within the same trial. Use the shared scorer unchanged for headline macro-F1 and accuracy. Retain planned trials, included model outcomes, valid labels, distinct instances, transformation clusters, families, and complete paired support separately. Missing infrastructure is not a wrong mathematical answer or a measured zero-cost attempt.
10. **Inspection:** Review every wrong valid answer and every unusable outcome in a claimed failure population. Assign mathematical error, expression/domain misreading, insufficient explanation, format-only failure, refusal, budget exhaustion, adapter/grader defect, infrastructure, or unresolved cause. Explanations can support a diagnosis but cannot establish hidden reasoning processes or an intention such as unwillingness to reason. A correct label with a bad explanation remains label-correct and gets a separate diagnostic flag.

## Uncertainty and comparisons

Headline metrics remain the shared scorer's pooled counts. Three trials describe repeated requests on each fixed task; they are not three independent mathematical tasks. The finite frozen-suite score is an exact description of observed responses, conditional on this execution. It does not itself need a sampling interval.

For uncertainty about resampling the declared synthetic population, use **10,000 deterministic percentile bootstrap replicates**, seed `coconut-quality-bootstrap-v1`. Resample complete transformation/parameter clusters with replacement **within broad family**, carrying all related labels, domain/representation controls, depths, and the three trials together. Recompute macro-F1/accuracy from retained outcomes, without re-running inference or reference verification inside the resampling loop. For paired cells, reuse each sampled cluster and retained trial indices in both cells, then compute the metric difference. Use nearest-rank empirical 2.5% and 97.5% quantiles. Record the cluster map, seed, replicate count, stratum sizes, and quantile rule.

Produce an interval only when all planned trials in both claimed comparison cells are included model outcomes, there are **at least 20 effective clusters overall**, and each broad family has **at least three effective clusters**. Otherwise report interval unavailable with the unmet support/completeness condition. Even an eligible interval is conditional on these fixed families and exchangeable parameter clusters; it does not quantify between-family generalization or prove independent task difficulty. Report both task and cluster counts. An interval collapsing at ceiling or zero error does not prove zero future error.

No global ordering claim follows from an interval alone. Predeclare a single primary contrast or disclose the full effort/model matrix as descriptive; no favorable post-hoc pair selection. A primary superiority claim additionally requires the paired difference interval to exclude zero, at least **0.05 macro-F1** observed improvement, complete matched work, and no unresolved format/budget/routing confound. This policy does not convert an effort comparison into equal-compute evidence. Sparse family/depth slices get counts and scores without unsupported uncertainty or ranking.

## Failure claims and gate decisions

G-QUALITY does not require model errors. It is Go only when each pitfall has a passed, repaired, or explicitly accepted scoped-limitation outcome, and all central references, retained evidence, denominators, comparison boundaries, and public claims are supported. An unresolved critical defect or missing evidence needed for a central claim yields No-go. A scoped limitation must name its population and restricted wording.

A **point counterexample** is a returned, completed, valid wrong label on an independently checked case with the exact transcript/settings retained. It supports only that observed error. A stronger claim of a **reproducible mathematical limitation** requires confirmation on at least **two non-equivalent core clusters in at least two broad families**, with at least **two valid wrong labels out of three trials on each case**, in a predeclared frontier-model cell using its highest verified supported effort in the experiment. All three trials must be completed and nontruncated; inspect every outcome and independently recheck those references. A format-only, refusal-only, truncation-only, low-effort-only, or infrastructure failure cannot satisfy this mathematical claim. If these criteria are unmet, G-SIGNAL remains No-go for that claim even when a useful platform and honest scores exist.

The dated model inventory identifies what “frontier” and “available” mean for this experiment using provider/model documentation and successful inference permission. A model listing or authentication probe alone is insufficient. Retain every attempted model/effort cell, including unsupported or unfinished ones. Never describe one provider's selected models as all language models. No construction guarantees that a particular present or future model will fail.

## Bounded work

Offline quality analysis handles at most 256 cases per report, preserving the existing native certification limits (depth 32, 256 node occurrences, 512 processed cells, 200,000 subtree evaluations, 192-bit precision, and the existing process deadline). Pairwise analysis is at most 32,640 pairs; unsupported equivalence is unknown. Reuse validated data for resampling. Cap report output at 16 MiB and fail explicitly on exceeded input/work limits. Report cold worker startup separately from batched certification. Performance targets are diagnostics, not a reason to accept an unresolved reference.

The initial live experiment has a shared ceiling of **8,192 charged inference attempts** across screening, capability probes and confirmation; conservatively count every inference send against that ceiling when billing is unknown. Concurrency is **at most twelve**, lowered on observed provider limits. Each inference attempt has a 180-second deadline; metadata has a 20-second deadline. No SDK retries; any explicit D-08 transport retry remains bounded, counts against the shared ceiling, and is retained. These limits use the user's existing OpenAI-only development authorization. Do not manufacture calls just because a budget remains. Stop/resume only at recorded boundaries; deadline exhaustion leaves planned work incomplete.

The dated inventory is `apps/api/data/experiments/openai-inventory-v1.json`. Screen every inventoried text-LLM ID, including aliases/snapshots as separately identified requests, across its documented supported reasoning efforts using a separately frozen **nine-case balanced screening suite and three trials**. Screen outcomes are exploratory; alias counts are not counts of independent architectures. Audio/image and other incompatible models remain explicitly excluded with reasons. Unsupported efforts and rejected calls remain recorded; never silently remove an effort setting. Before any screening results are inspected, freeze the frontier subset and supported effort matrix for the **full 72-case held-out confirmation suite** using inventory/documentation and inference permission, not screen scores. Any later selected subset is exploratory and needs a new confirmation cycle.

Historical version-1 profiles keep their 4,096-token ceiling unchanged. The new explicitly identified reasoning-profile family uses **16,384 output tokens per attempt for every reasoning effort** and separately binds format/effort/ceiling in comparison identity. A 72-task three-trial cell needs 216 logical calls and a requested output ceiling of **3,538,944 tokens** at 16,384 per attempt, before explicit retries; a nine-case screening cell needs 27 calls and a 442,368-token requested ceiling. The shared maximum requested output across 8,192 such attempts is 134,217,728 tokens. These are work ceilings, not usage or currency estimates. A larger ceiling requires a new profile/version and separate analysis; truncation or exhausted reasoning budget never becomes evidence of a wrong mathematical label. The concrete experiment manifest must identify which nonreasoning cells, if any, use another separately named ceiling.

## Independently checkable richer candidates

These formulas are new design examples in project terminology, not established model-hard tasks. All use supported operations. Derivatives below are algebraic references derived independently of the interval evaluator. For an affine inner variable `t=ax+b`, with `a != 0`, multiply each listed second derivative by `a²` and evaluate the exact transformed interval. Do not claim that every further nonlinear substitution preserves its sign.

| Broad family / formula | Independent second derivative | Three checked label regimes |
| --- | --- | --- |
| Local logarithm: `log(1+t²)` | `2(1-t²)/(1+t²)²` | Convex `[-1/2,1/2]`; concave `[2,3]`; neither `[0,2]`. |
| Reciprocal exponential: `1/(1+exp(t))` | `exp(t)(exp(t)-1)/(1+exp(t))³` | Convex `[1,2]`; concave `[-2,-1]`; neither `[-1,1]`. |
| Exponential/quadratic competition: `exp(t)-t²/2` | `exp(t)-1` | Convex `[1,2]`; concave `[-2,-1]`; neither `[-1,1]`. |
| Rational bend: `t²/(1+t²)` | `2(1-3t²)/(1+t²)³` | Convex `[-1/4,1/4]`; concave `[1,2]`; neither `[0,1]`. |
| Rounded/quadratic competition: `sqrt(1+t²)-a t²` | `(1+t²)^(-3/2)-2a` | On `[-1,1]`: convex `a=1/8`; concave `a=5/8`; neither `a=1/4`. |
| Softplus/quadratic competition: `log(1+exp(t))-a t²` | `exp(t)/(1+exp(t))²-2a` | On `[-1,1]`: convex `a=1/16`; concave `a=9/64`; neither `a=7/64`. |
| Squared bend: `(t²-t)²+a t²` | `12(t-1/2)²-1+2a` | On `[0,1]`: convex `a=1`; concave `a=-2`; neither `a=1/4`. |
| Exponential bowl: `exp(t²/4)-a t²` | `exp(t²/4)(1/2+t²/4)-2a` | On `[-1,1]`: convex `a=1/8`; concave `a=5/8`; neither `a=3/8`. |
| Mixed branches: `log(1+exp(2t))+sqrt(1+t²)-a t²` | `4exp(2t)/(1+exp(2t))²+(1+t²)^(-3/2)-2a` | On `[-1,1]`: convex `a=1/8`; concave `a=5/4`; neither `a=3/4`. |

An ephemeral local Python check of these 27 examples passed the current native certifier without changing source or making inference calls. The first 24 examples took 40.2 ms inside the already-started process; the mixed-branch cases took 11.9/8.9/0.9 ms individually. These are one-shot feasibility observations, not a throughput benchmark. They do not include environment/startup cost and establish no model difficulty.

Useful independent bounds include `e^u < 1/(1-u)` for `0<u<1`, obtained by bounding the exponential series termwise by the geometric series. For softplus competition at `a=7/64`, the curvature is positive at zero; at `t=3/4`, `exp(t)>269/128>21/10`, so its logistic curvature is less than `210/961<7/32`, giving a strict negative witness. For mixed branches with `a=3/4`, curvature at zero is `1/2`; at `t=3/4`, `exp(3/2)>4`, so the sum of positive terms is below `16/25+64/125=144/125<3/2`. Review parameter perturbations separately; these checked examples do not certify an arbitrary parameter box.

### Expanded polynomial curvature

For a rational polynomial `p(x)=sum p_j x^j`, form the exact rational coefficients of `q(x)=p(x)²-epsilon` and integrate twice to obtain `F`, with `F''=q`. Render a zero-pruned expanded/Horner expression; retain the exact coefficient identity privately as independent reference evidence. This produces algebraic cancellation and multiple curvature transitions without manufactured depth.

- If `epsilon<0`, then `F''>=-epsilon>0`, proving strict convexity.
- On `[-1,1]`, `|p(x)|<=sum |p_j|`. Choosing `epsilon>(sum |p_j|)²` proves strict concavity.
- For positive `epsilon`, a rational root `r` strictly inside the interval gives `F''(r)=-epsilon<0`. A separate rational point with `p(s)²>epsilon` supplies the positive witness and proves neither. Both witnesses are required.

With roots `-3/4,-1/4,1/4,3/4`, a zero-pruned Horner presentation had measured depth 14 and 29 nodes. Convex margins `-epsilon=1/64,1/256,1/1024` certified in single samples of 19.5/43.5/98.5 ms with 24/64/144 cover leaves. A smaller margin `1/4096` in an earlier unpruned presentation exhausted the existing work bound; preserve that unverified result instead of relaxing admission. A negative-curvature well between sample points is a valuable control, but already exists in the verifier regression suite and is not a new diversity family by itself.

Related but equivalent controls include repeated `log(exp(u))`, valid-domain `exp(log(u))`, double negation, zero/one arithmetic, and repeated softplus: `softplus(softplus(u))=log(2+exp(u))`. Their diagnostic value is detecting fake depth and representation sensitivity. They do not justify independent deep-reasoning coverage. Do not extend the operation set, domain boundary, verifier precision, or resource policy merely to admit a failed candidate.

## Provenance and research limits

Prior work: Yepeng Liu, Yu Huang, Yu-Xiang Wang, Yingbin Liang, and Yuheng Bu, *ConvexBench: Can LLMs Recognize Convex Functions?*, [arXiv v2](https://arxiv.org/abs/2602.01075v2), revised February 4, 2026. The complete HTML manuscript and the PDF-only prompt text on pages 17–18 were read for this review. Existing prompt provenance remains in [prompt-adaptation.md](prompt-adaptation.md).

**Source paraphrase:** The study generates composition-rule examples, uses counterexample filtering for neither, and compares raw, decomposed, and recursive methods. Its experiments use different sampling procedures across model groups and a much larger reasoning ceiling. Those results do not transfer to this project's scalar certified suites, current models, budgets, or prompt contract. Claims about insufficient reasoning effort or internal model processes require new controlled evidence; a falling token count alone does not establish a mechanism. This project's independent global certification and explicit failure accounting remain its own implementation boundary. The manuscript links CC BY-NC-SA 4.0; no source code, prompts, datasets, or visual assets were copied for these candidate families.

The [CVXPY primary tutorial](https://www.cvxpy.org/tutorial/dcp/index.html#example-2), read in full, documents that sufficient composition analysis can return unknown for a truly convex expression such as `sqrt(1+x²)`. This corroborates the policy distinction between unverified and neither. The derivative identities and polynomial construction above are independently derived elementary mathematics; they are not attributed to prior experimental results. Neither an AI-assisted mathematical review nor agreement with the same native library is a substitute for a recorded independent expert review where a public claim requires one.
