# Module 08: foreground runs and retained results

## Scope and decisions

Join verified suite artifacts, module 07 single-attempt inference, all three fresh trials, and the shared scorer. Existing D-02–D-08 remain binding. Run settings choose one explicit provider/model/route/profile; no retry, hidden compatibility inference, model substitution, or changed task membership occurs. The new challenge suite is an additional generator identity; historical exact/smooth artifacts remain reproducible. A selected profile produces a separately retained, profile-bound suite artifact with the same mathematical cases, never forged evidence under a different profile.

**D-09:** Runs are private by default and retained for seven days in local SQLite. Creation returns a random private access code once; only its SHA-256 hash is stored. The browser holds it in current-page memory, may explicitly copy/save it, and requires re-entry to return after refresh. It is separate from the provider key. Private read/export/delete/publication needs this code. There are no accounts or implicit public links. Publication is explicit, reversible, and subject to module 10 eligibility; expiry/deletion removes public visibility and underlying evidence together. Exported results contain no provider key or run-access code.

Runs remain foreground streamed operations. Disconnect/cancellation aborts active calls and preserves completed work; server restart marks unfinished records interrupted. Resumption is not supported; a new paid run requires a fresh key and intentional launch. No saved credential, detached worker, automatic paid recovery, or development-key visitor fallback exists. Already-sent upstream work/charges may remain unknown.

## Architecture and ownership

1. `runs/types.ts`: strict request, retained record, actual progress, streamed events, store interfaces, and suite-key contracts. Root owns these types and executor integration.
2. `runs/registry.ts`: allowlisted verified artifacts for `reference-v1`, `smooth-v2`, `challenge-v1`, and disjoint `screening-v1`; bounded immutable cache keyed by suite/profile. Regenerate and replay a profile-specific artifact rather than weaken scorer identity binding. Public suite descriptions expose coverage/settings, not private case labels or certificates. Assigned worker owns this file and tests.
3. `runs/store.ts`: SQLite with private access hash, seven-day expiry, revision checks, private/public reads, reversible publication, deletion and restart interruption. Database lives under ignored `apps/api/data/private/`, with restrictive local permissions. No provider credential is an accepted stored field. Assigned worker owns this file and tests.
4. `runs/engine.ts`: one foreground run, fixed complete planned trial population, concurrency 1–12, at most four active runs per process, 60-minute run deadline, cancellation and fatal-provider stopping. Persist every finished inference result and explicit unattempted trial; finalize through `scoreEvaluation`. Root owns.
5. `runs/routes.ts`: fixed origin/TLS/no-cache/bounded JSON boundary and `application/x-ndjson` events for start/progress/terminal outcomes. Bearer provider key only launches work; private access code authenticates later result operations. GET suite/policy metadata is public. Root owns; module 09 consumes this contract.
6. `runs/cli.ts`: explicit provider-matched environment credential and bounded foreground execution; safe final export. Development experiment scheduling reuses the same engine, records every cell and respects the shared D-12 ceiling. No external deployment/submission is included.

Reuse Bun's built-in SQLite and current dependencies. New artifacts dispatch by exact format/generator identity through `suites/artifact.ts`; scorer math/denominators remain unchanged. Scoring replays retained inputs and receives a record for every planned case/trial, including unattempted ones. Run records retain profile-bound suite, exact prompts/results, requested/effective identity/settings, usage/cost uncertainty, wall time/concurrency, planned/actual send counts, and full safe outcome evidence.

## API and states

- `GET /runs/policy` and `GET /runs/suites`: nonsecret limits and actual verified suite/profile choices.
- `POST /runs`: JSON suiteKey/provider/modelId/servingProvider/profileId/concurrency/acceptCharges, explicit visitor bearer. Returns newline-delimited `started`, `progress`, and `finished`/`error` events. Start carries the private access code once; progress contains measured counts only. The HTTP exchange stays open until settlement.
- `GET /runs/:id`, `GET /runs/:id/export`, `DELETE /runs/:id`, and `POST /runs/:id/publication`: private access bearer required; no credentials in URL/query/body logs.
- `GET /runs/:id/public`: only explicitly published, unexpired evidence. Module 10 owns public listing/ranking and final eligibility.

Progress tracks planned, started, active, finished, included-model, infrastructure-failed and remaining trials plus actual inference sends. Remaining means all unfinished trials; active is a subset, and queued is remaining minus active. There is no fabricated ETA. A complete model population may contain incorrect/invalid/refused/truncated model outcomes; infrastructure failures or unattempted work keep the run failed/partial and its report provisional/unavailable. States are running, cancelling, completed, cancelled, timed-out, failed, and interrupted. A success HTTP status alone proves no evaluation result.

The request body is at most 4 KiB with fatal UTF-8 and a bounded ingress deadline. Known suites contain at most 75 cases; reject unknown suite IDs or arbitrary file paths. Bound retained run JSON to 256 MiB and fail explicitly on storage/work limits. No body/parser error exposes raw upstream messages, private access codes, keys or file paths. Heartbeats may keep the stream open but never increment progress. Stop new work and abort active work on authentication/permission/quota rejection; retain every already-observed outcome and remote uncertainty.
