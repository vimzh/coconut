# Long-deadline reserve diagnostic implementation plan

This plan precedes implementation. The standard reserve exhausted its 180-second provider deadline before any model outcome: eight dispatched requests had unknown remote outcomes, and 100 trials remained unattempted. One separate `long-reserve-v1` research method will request all 18 unchanged tasks afresh, three trials per task and both declared models. Selection follows deadline censoring, not correctness; no answer was observed. Nothing resumes or rewrites the standard population.

1. Freeze a distinct research manifest with the unchanged suite/prompt/review/proposal identities, 600,000 milliseconds per inference, 90 minutes for the complete study, four operations per model, eight total, 16,384 output tokens, max effort and zero retries. Verify that no normal platform profile, 180-second transport bound, RunView, scoring report or leaderboard contract changes.
2. Require exactly five terminal studies in coordinator-provided actual-send accounting: original, replication, interior, remaining-models and conditional-reserve. Reuse strict per-attempt reconciliation and hash-bind the standard reserve's manifest, final ledger, primary reconciliation and eight-unknown-send proof. Count 183 old controls and allowance four once. Require 7,746 prior conservative actual sends plus 108 maximum fresh sends, yielding 7,854 within 8,192. Verify absent/active/tampered accounting refuses freeze.
3. Reuse pure Responses request construction, response normalization and answer extraction. Use the official pinned, patched OpenAI SDK through a new operator-only factory: explicit credential, fixed Responses POST, reconstructed authorization/content-type headers, null ambient routing/secrets, no logging and no retries. Bound the complete body to one MiB, visible text to 131,072 code units, and all operations to their declared deadlines. Verify endpoint/body/header isolation, store=false, exact prompts/settings, cancellation, secret rejection and zero retries using injected HTTP fixtures only.
4. Persist each dispatch authorization and increment its conservative send count before the one wire POST. Retain research-only raw/normalized responses and all failures privately. Stop further dispatch on infrastructure failures, preserve peer cancellation and every unattempted trial, and never start replacement requests. Verify dispatch count never exceeds 108 and outcome denominators remain 54 per model.
5. Require explicit research publication. Export only complete qualified model populations, with descriptive answer/label counts and full/unavailable denominators; omit raw infrastructure failures from public artifacts. Publish no normal application run links, RunViews, official score/report IDs or leaderboard entries. Retain all prior records and use exclusive new paths. Verify incomplete publication, reflection, overwrite and persistence failures remain unsuccessful and observable.
6. Run focused tests, API lint, type checking and build, then hand off for independent review. No credential read, freeze, paid request, API restart, database operation or commit occurs during implementation. The coordinator supplies the final five-study accounting artifact and controls any later intentional freeze/launch.
